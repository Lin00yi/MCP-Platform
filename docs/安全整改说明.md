## 2. 清理 Git 历史（需人工确认后执行）

当前提交历史仍包含旧凭据。**轮换凭据后**，可用 BFG 清理（重写历史，需团队协调）：

```bash
# 1) 备份仓库
git clone --mirror git@your.gitlab/mcp-gateway.git mcp-gateway-backup.git

# 2) 用 BFG 删除敏感文件历史（示例）
java -jar bfg.jar --delete-files application-prod.yml
java -jar bfg.jar --delete-files ExecuteControllerTest1.java
java -jar bfg.jar --replace-text passwords.txt   # 每行一个旧密码/密钥

# 3) 清理并强推
git reflog expire --expire=now --all
git gc --prune=now --aggressive
git push --force
```

> 若无法重写历史，至少确保上述凭据已全部失效——失效后的泄露值不再有利用价值。

## 3. 配置环境变量

参考 `mcp-gateway/.env.example`，至少配置：

```bash
MCP_DB_URL=...
MCP_DB_USERNAME=...
MCP_DB_PASSWORD=...
MCP_SECURITY_SECRETKEY=$(openssl rand -base64 32)
MCP_ADMIN_JWT_SECRET=$(openssl rand -base64 48)
MCP_ADMIN_INIT_PASSWORD=...        # >= 8 位，首次启动后立即修改
MCP_SWAGGER_ENABLED=false
MCP_SECURITY_ALLOW_PRIVATE_NETWORK=false   # 下游均为内网时才改 true
```

生产环境缺少 `MCP_SECURITY_SECRETKEY` / `MCP_ADMIN_JWT_SECRET` 会**启动失败**，这是刻意设计。

## 4. 数据库迁移

对存量库执行 `docs/sql/migration.sql` 末尾「5. 安全整改」部分：

- `operation_log.tenant_id`
- `grant_request.tenant_id`
- `tool_call_record (tenant_id, create_time)` / `(server_id, create_time)` 索引

> MySQL 8.0 不支持 `ADD COLUMN IF NOT EXISTS`，执行前先确认列不存在。

新增列后：
- 历史 `operation_log` / `grant_request` 的 `tenant_id` 为 NULL，非超管将看不到这些历史行（符合隔离预期）；
- 如需回填，可按 `resource_type/resource_id` 关联 `mcp_server` 手工补数。

## 6. 已知残余风险（本轮未完全消除）

1. **应用（enn_app_info）是全局表**，没有 tenant_id；租户管理员仍可看到全部 appId（密钥已脱敏）。彻底解决需增加应用归属字段并做数据迁移。
2. **SSRF 的 DNS rebinding**：校验时解析一次、实际连接时可能再次解析。高安全场景建议出网代理 + 域名白名单。
3. **控制台 token 存 localStorage**：XSS 仍可窃取。建议后续加 CSP、缩短 token 有效期或改为 HttpOnly Cookie + CSRF 防护。
4. **多实例部署**：登录限流、session/SSE 注册表、上游会话映射都是进程内实现，多副本需替换为 Redis。
5. **上游 MCP server 鉴权**：当前未向 downstream 透传/配置独立凭证，下游需要鉴权时需另行扩展。
6. **Git 历史**：需按第 2 节人工清理。
