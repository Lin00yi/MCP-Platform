# MCP 网关后端接口调用示例

> **2026-10 认证变更**：网关只认 `x-dsh-auth-token`（`dsh_` / PAT）；应用创建、`appId`/`appSecret`、应用级授权与 `access-token` 已移除。本文中相关历史段落已过期，以 [README](../README.md) 与 [MCP客户端接入指南](MCP客户端接入指南.md) 为准。

> 后端端口 `8081`，应用侧 MCP 端点由 `mcp_server` 表动态注册（seed 中为 `/mcp/v1/core`、`/mcp/greatgas/core`）。
> 后台管理接口统一返回 `Result<T>` 信封 `{code, message, data}`（`code=0` 成功）。

---

## 0. 先决条件：数据库已迁移到新模型

改造后代码读取 `tenant / mcp_server / mcp_tool / mcp_prompt / mcp_resource / app_server_rel / app_tool_rel` 表。
如果数据库还是旧的 `tenant_api / method_def / ...` 结构，会表现为：

- 启动日志出现 `刷新失败：...Table 'mcp_gateway.mcp_server' doesn't exist...`
- `/mcp/v1/core` 等动态 MCP 端点 **404**（动态注册失败）
- `/mcp/admin/*` 返回 `{code:500, message:"...表不存在..."}`

修复（二选一）：
- 本地 Docker（3307）：`docker compose down -v && docker compose up -d --build`（会重新执行 `docker/mysql/init.sql`）
- 存量库：执行 `docs/sql/migration.sql`

## 1. 后台管理接口（curl）

### 1.1 登录（取管理 token）

```bash
curl -s -X POST http://localhost:8081/mcp/admin/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
# → {"code":0,"message":"ok","data":{"token":"<JWT>","user":{"id":1,"username":"admin","role":"SUPER_ADMIN",...}}}
```

后续管理请求带 `Authorization: Bearer <token>`：

```bash
TOKEN="<上一步的 token>"

# 业务方列表
curl -s http://localhost:8081/mcp/admin/tenants -H "Authorization: Bearer $TOKEN"

# MCP Server 列表
curl -s http://localhost:8081/mcp/admin/servers -H "Authorization: Bearer $TOKEN"

# 工具列表
curl -s http://localhost:8081/mcp/admin/tools -H "Authorization: Bearer $TOKEN"

# Prompt / Resource 列表
curl -s http://localhost:8081/mcp/admin/prompts -H "Authorization: Bearer $TOKEN"
curl -s http://localhost:8081/mcp/admin/resources -H "Authorization: Bearer $TOKEN"

# 应用列表 / server 授权 / tool 授权
curl -s http://localhost:8081/mcp/admin/apps -H "Authorization: Bearer $TOKEN"
curl -s http://localhost:8081/mcp/admin/app-server-rels -H "Authorization: Bearer $TOKEN"
curl -s http://localhost:8081/mcp/admin/app-tool-rels -H "Authorization: Bearer $TOKEN"
```

### 1.2 新增一个 Server 并授权

```bash
# 新增 Server（归属业务方 1）
curl -s -X POST http://localhost:8081/mcp/admin/servers \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"tenantId":1,"name":"crm-report","path":"/mcp/v1/report","status":1,"capabilitiesJson":"{\"protocolVersion\":\"2024-11-05\",\"capabilities\":{\"tools\":{}},\"serverInfo\":{\"name\":\"mcp-transfer\",\"version\":\"1.0.0\",\"title\":\"CRM Report MCP\"}}"}'

# 刷新动态端点（让新 path 生效）
curl -s -X POST http://localhost:8081/mcp/admin/refresh-server-api -H "Authorization: Bearer $TOKEN"

# 为应用 crm 授权该 server
curl -s -X POST http://localhost:8081/mcp/admin/app-server-rels \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"appId":"crm","serverId":2}'
```

### 1.2.1 设置工具治理策略（白名单 / META / 阈值）

```bash
# 查看预算（全部 Server 或单个 Server）
curl -s http://localhost:8081/mcp/admin/servers/budgets -H "Authorization: Bearer $TOKEN"
curl -s "http://localhost:8081/mcp/admin/servers/2/tool-budget?appId=crm" -H "Authorization: Bearer $TOKEN"

# 设为白名单 + META，并指定热工具
curl -s -X PUT http://localhost:8081/mcp/admin/servers/2/tool-exposure \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"toolAccessMode":"WHITELIST","toolExposureMode":"META",
       "hotToolCodes":["query-customer","create-order"],
       "toolWarnThreshold":100,"toolMaxThreshold":500}'

# 按近 30 天成功调用推荐热工具
curl -s "http://localhost:8081/mcp/admin/servers/2/hot-tools/recommend?days=30&limit=20" \
  -H "Authorization: Bearer $TOKEN"
```

### 1.3 从 REST / OpenAPI 生成 Tool

**单个接口（REST 示例 → 草稿，不落库）**：

```bash
curl -s -X POST http://localhost:8081/mcp/admin/tools/from-rest \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"查询客户","code":"query-customer","description":"按 ID 查询","method":"GET",
       "url":"https://api.example.com/users/{id}?region={region}&lang=zh","authType":"NONE"}'
# → 返回 serviceUrl / requestType / authType / resJson / paramMapping，前端回填表单后由用户确认保存
```

**整份 openapi.json（预览 + 批量导入）**：`document` 为 OpenAPI 3.x 原文（字符串），
`baseUrl` 可覆盖 `servers[0].url`；`codes` 为要导入的 operationId（省略=全部，空数组=不导入）。

```bash
# 预览：解析 + 前置校验，返回每个 operation 的草稿（code/路径/方法/入参/映射/问题），不落库
python3 -c 'import json;print(json.dumps({"serverId":2,"document":open("openapi.json").read()}))' > /tmp/openapi-preview.json
curl -s -X POST http://localhost:8081/mcp/admin/tools/openapi/preview \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @/tmp/openapi-preview.json

# 导入：conflictPolicy=SKIP（默认，已存在同 code 跳过）| OVERWRITE（覆盖已有工具）
python3 -c 'import json;print(json.dumps({"serverId":2,"document":open("openapi.json").read(),"conflictPolicy":"SKIP","codes":["orders","quotations"]}))' > /tmp/openapi-import.json
curl -s -X POST http://localhost:8081/mcp/admin/tools/openapi/import \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @/tmp/openapi-import.json
# → {"created":2,"updated":0,"skipped":0,"failed":0,"failures":[],"baseUrl":"..."}
```

前置校验（ERROR 阻塞该项导入，WARN 仅提示）：

- 文档必须是 OpenAPI 3.x（Swagger 2.0 直接拒绝）；`paths` 非空；`baseUrl` 必须 http(s) 绝对地址
- 网关运行时只支持 **GET/POST**，PUT/PATCH/DELETE 等标记为不可导入
- 本地 `$ref` 解析、`allOf` 合并；**外部 `$ref` 拒绝**；`nullable` 转为联合类型
- 请求体仅支持 `application/json`；`multipart/form-data` 拒绝；自由格式 body 仅在无其他映射时允许透传
- `code` 由 `operationId` 生成（非法字符替换、超长截断、同文档重名加后缀）；与 Server 下已有 code 冲突需按策略处理
- path 占位符未声明参数时按 string 补全；cookie 参数、query 数组/对象序列化给出警告
- `apiKey(header)` → API_KEY、`http bearer` → BEARER 自动生成鉴权骨架，凭证仍需保存后手工填写
- `baseUrl` 命中 SSRF 策略时提示（内网地址需 `MCP_SECURITY_ALLOW_PRIVATE_NETWORK=true`）

## 2. MCP 协议接口（应用侧客户端）

端点：`POST /mcp/v1/core`，请求体为 JSON-RPC 2.0，支持 **MCP Streamable HTTP** 传输。
握手方法（`initialize`/`ping`/`notifications/*`）**无需鉴权**；其余 MCP 方法需带 `Mcp-Session-Id`；
除 `initialize`/`ping`/`notifications/*` 外，所有方法都需带 `access-token`（HS256 JWT，`iss`=appId，用 `app_secret` 验签）。

> **会话流程（Streamable HTTP）**：先 `initialize` → 从响应头取 `Mcp-Session-Id` → 后续所有请求带上该头。
> 通知类（无 `id`）返回 `202`；不带 session 的请求返回 `400`。

### 2.1 initialize（返回 Mcp-Session-Id）

```bash
curl -s -D - -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test-client","version":"1.0.0"}}}'
# 响应头含：Mcp-Session-Id: <uuid>
# 响应体：{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2024-11-05","capabilities":{"tools":{}},"serverInfo":{...}}}
```

### 2.2 tools/list（带 Mcp-Session-Id）

```bash
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' \
  -H 'Mcp-Session-Id: <上一步返回的 session id>' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
# → {"jsonrpc":"2.0","id":2,"result":{"tools":[{"name":"select-policy-region-by-regin","description":"...","inputSchema":{...}}, ...],
#      "_meta":{"totalTools":35,"visibleTools":35,"returned":35,"accessMode":"WHITELIST","exposureMode":"DIRECT",...}}}
```

工具数超过 `MCP_TOOLS_PAGE_SIZE` 时，响应带 `nextCursor`，下一页请求：

```bash
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' -H 'Mcp-Session-Id: <session id>' \
  -d '{"jsonrpc":"2.0","id":21,"method":"tools/list","params":{"cursor":"<nextCursor>"}}'
```

META 模式下 `tools/list` 只返回热工具 + 元工具，调用示例：

```bash
# 检索（只返回 name/description/tags）
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' -H 'Mcp-Session-Id: <session id>' \
  -H 'Authorization: Bearer <app token>' \
  -d '{"jsonrpc":"2.0","id":22,"method":"tools/call",
       "params":{"name":"search_tools","arguments":{"query":"订单 退款","limit":10}}}'

# 执行
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' -H 'Mcp-Session-Id: <session id>' \
  -H 'Authorization: Bearer <app token>' \
  -d '{"jsonrpc":"2.0","id":23,"method":"tools/call",
       "params":{"name":"call_tool","arguments":{"name":"refund_apply","arguments":{"orderNo":"A1"}}}}'
```

### 2.3 prompts/list / resources/list（带 Mcp-Session-Id）

```bash
curl -s -X POST http://localhost:8081/mcp/v1/core -H 'Content-Type: application/json' \
  -H 'Mcp-Session-Id: <session id>' \
  -d '{"jsonrpc":"2.0","id":3,"method":"prompts/list"}'

curl -s -X POST http://localhost:8081/mcp/v1/core -H 'Content-Type: application/json' \
  -H 'Mcp-Session-Id: <session id>' \
  -d '{"jsonrpc":"2.0","id":4,"method":"resources/list"}'
```

### 2.4 tools/call（需 access-token）

先生成 `access-token`（HS256，`iss` 填 appId，用该应用的 `app_secret` 签名，示例 app `crm` / `crm_secret_placeholder`）：

```bash
python3 - <<'PY'
import hmac, hashlib, base64, json, time
def b64(b): return base64.urlsafe_b64encode(b).rstrip(b'=').decode()
secret = "crm_secret_placeholder"          # app_id=crm 的 app_secret
header  = {"alg":"HS256","typ":"JWT"}
payload = {"iss":"crm","exp":int(time.time())+86400,"iat":int(time.time())}
h = b64(json.dumps(header,separators=(",",":")).encode())
p = b64(json.dumps(payload,separators=(",",":")).encode())
si = f"{h}.{p}"
s = b64(hmac.new(secret.encode(), si.encode(), hashlib.sha256).digest())
print(si + "." + s)
PY
```

调用：

```bash
ACCESS_TOKEN="<上一步生成的 JWT>"

# 本地反射工具（server=1，应用 crm 已被授权整个 server）
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' \
  -H 'Mcp-Session-Id: <session id>' \
  -H "access-token: $ACCESS_TOKEN" \
  -H 'Authorization: Bearer sk-1001' \
  -d '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"select-policy-region-by-regin","arguments":{"region_name":"北京"}}}'

# HTTP 转发 + SK_EXCHANGE 工具（Authorization 里的 sk 用于向下游换 token）
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' \
  -H 'Mcp-Session-Id: <session id>' \
  -H "access-token: $ACCESS_TOKEN" \
  -H 'Authorization: Bearer sk-1001' \
  -d '{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"get-enable-zones","arguments":{}}}'
```

> 权限说明（级联）：授权分两级——先授权 server（`app_server_rel`），再可选加 tool 白名单（`app_tool_rel`）。
> - `crm`：`app_server_rel(crm, server=1)` 且无白名单 → server 1 内全量放行；
> - `greatgas`：`app_server_rel(greatgas, server=1)` + `app_tool_rel(greatgas, 12)` 白名单 → 仅能调 `get-enable-zones`；
> - 未授权 server 的应用，即使有 tool 白名单也一律 403（tool 授权依赖 server 授权）。

## 3. MCP 客户端配置

### 3.1 Claude Desktop / 通用（HTTP `url` 方式）

本网关支持 **MCP Streamable HTTP**（`initialize` 返回 `Mcp-Session-Id`，后续请求自动携带），可用标准 MCP 客户端以 `url` 挂载：

```json
{
  "mcpServers": {
    "crm": {
      "url": "http://localhost:8081/mcp/v1/core"
    },
    "greatgas": {
      "url": "http://localhost:8081/mcp/greatgas/core"
    }
  }
}
```

> 注意：除握手方法外，所有方法都需要 `access-token` 头，标准 MCP SDK 客户端默认不携带该头。
> 若客户端不支持自定义请求头，需在网关层对 trusted 客户端放行，或改用下述编程式方式注入 token。

### 3.2 编程式（Node + @modelcontextprotocol/sdk，注入 access-token）

```ts
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StreamableHTTPClientTransport } from "@modelcontextprotocol/sdk/client/streamableHttp.js";

const transport = new StreamableHTTPClientTransport(
  new URL("http://localhost:8081/mcp/v1/core"),
  {
    requestInit: {
      headers: {
        "access-token": "<HS256 JWT，iss=你的 appId>",
        Authorization: "Bearer <sk，SK_EXCHANGE 工具需要>",
      },
    },
  },
);

const client = new Client({ name: "demo", version: "1.0.0" });
await client.connect(transport);

const { tools } = await client.listTools();
const result = await client.callTool({
  name: "select-policy-region-by-regin",
  arguments: { region_name: "北京" },
});
```

### 3.3 deep-agent 风格（原网关设计目标，raw JSON-RPC）

直接对端点 POST JSON-RPC，握手（`initialize`/`ping`/`notifications/*`）不带 token，其余方法（含 `tools/list`、`tools/call`）都要带 `access-token`：

```bash
# initialize（无 token）
curl -s -X POST http://localhost:8081/mcp/v1/core -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"deep-agent","version":"1.0"}}}'

# tools/call（带 access-token）
curl -s -X POST http://localhost:8081/mcp/v1/core \
  -H 'Content-Type: application/json' -H "access-token: $ACCESS_TOKEN" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"<your-tool>","arguments":{}}}'
```

## 4. 错误码速查

| code | 含义 |
|---|---|
| -32700 | JSON 解析错误 |
| -32600 | 无效请求 |
| -32601 | 方法不存在 |
| -32602 | 参数无效 |
| -32603 | 内部错误 |
| -32001 | 未认证（access-token 缺失/验签失败） |
| -32002 | 资源不存在（server/tool 不存在或未启用） |
| -32003 | 无权限（app 未授权该 server/tool） |
