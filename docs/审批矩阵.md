# 审批矩阵（RBAC + Maker-Checker）

> **2026-10 认证变更**：网关只认 `x-dsh-auth-token`（`dsh_` / PAT）；应用创建、`appId`/`appSecret`、应用级授权与 `access-token` 已移除。本文中相关历史段落已过期，以 [README](../README.md) 与 [MCP客户端接入指南](MCP客户端接入指南.md) 为准。

> 适用范围：`mcp-console` 管理控制面板与 `/mcp/admin/**` 控制面接口。
> 事实来源：`ApprovalAction` / `ApprovalTier` / `ApprovalPolicy`（后端），前端通过
> `GET /mcp/admin/approvals/policy` 拉取同一份矩阵。

## 1. 角色

| 角色 | 等级 | 范围 | 定位 |
|---|---|---|---|
| `SUPER_ADMIN` | 4 | 全局 | 平台超管 |
| `ADMIN` | 3 | 本业务方 | 租户管理员（含用户管理） |
| `DEVELOPER` | 2 | 本业务方 | 开发者（Server/Tool/授权） |
| `OPERATOR` | 1 | 本业务方 | 运维（只读 + 刷新 + 导出） |
| `USER` | 0 | 本业务方 | 只读 |

## 2. 风险分档

| 档位 | 含义 | 直接执行角色 | 发起门槛 | 审批人 |
|---|---|---|---|---|
| **L1** | 租户内低风险写 | DEVELOPER | DEVELOPER | 不审批，只审计 |
| **L2** | 租户内高影响（授权/连接/下游凭证） | ADMIN | DEVELOPER | 管理员及以上 |
| **L3** | 平台凭证与提权 | SUPER_ADMIN | ADMIN | 平台超管 |
| **L4** | 平台治理 | SUPER_ADMIN | 不可申请 | 不审批，强审计 + 二次确认 |

规则：**直接执行角色的等级 ≥ 档位角色 → 直接执行；低于档位但达到发起门槛 → 必须审批。**

## 3. 动作清单

### L1（直接执行 + 审计）

- Tool / Prompt / Resource 的增删改、启停、版本变更
- Tool 连通性测试、REST 草稿生成
- 刷新动态端点、导出日志、查看监控

### L2（开发者需审批，管理员直接执行）

| 动作码 | 说明 |
|---|---|
| `GRANT_SERVER` / `GRANT_SERVER_BATCH` | 应用 × Server 授权（含批量） |
| `GRANT_TOOL` / `GRANT_PROMPT` / `GRANT_RESOURCE` | 应用 × 资产白名单授权 |
| `REVOKE_SERVER` / `REVOKE_TOOL` / `REVOKE_PROMPT` / `REVOKE_RESOURCE` | 撤销授权 |
| `SERVER_CREATE` | 创建 MCP Server |
| `SERVER_UPDATE_CONNECTION` | 变更连接配置（path / upstream_url / 身份断言） |
| `SERVER_DELETE` | 删除 MCP Server |
| `TOOL_CREDENTIAL_UPDATE` | 变更 Tool 下游凭证（auth_config） |

### L3（管理员需审批，开发者不可发起）

| 动作码 | 说明 |
|---|---|
| `APP_CREATE` | 创建应用并颁发 app_secret |
| `APP_RESET_SECRET` | 重置应用密钥 |
| `APP_DELETE` | 删除应用 |
| `USER_ROLE_UPDATE` | 变更用户角色（不能授予 `SUPER_ADMIN`） |

### L4（仅超管，不走审批）

- `TENANT_CREATE` / `TENANT_UPDATE` / `TENANT_DELETE`
- 平台安全配置、密钥轮换（环境变量，不在控制台）

## 4. 硬规则

1. **审批人 ≠ 申请人**。
2. **审批人角色必须严格高于申请人**（DEVELOPER → ADMIN，ADMIN → SUPER_ADMIN）。
3. **有审批要求的操作不能保留直写入口**：开发者调用直写接口返回 `code=428`，
   提示走审批；管理员及以上才可直接执行。
4. **按快照执行**：申请单保存 `payload`，通过后按快照执行，避免“申请 A、批 B”。
5. **执行前再校验**：租户、资源存在性、应用与 Server 同租户。
6. **失败回滚**：执行异常时事务整体回滚，申请单保持 `PENDING`。
7. **并发安全**：审批时 `SELECT ... FOR UPDATE` + `UPDATE ... WHERE status='PENDING'`。
8. **快照加密落库**：`payload` 用 `SecretCrypto`（AES-256-GCM）加密；详情展示时对
   `authConfig` / `appSecret` / `token` 等字段脱敏。

## 5. 状态机

```
PENDING ──approve──▶ APPROVED（执行成功）
   │
   ├──reject──▶ REJECTED
   └──cancel──▶ CANCELLED（仅申请人）
```

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/mcp/admin/approvals/policy` | 当前角色的动作矩阵 |
| GET | `/mcp/admin/approvals?scope=pending\|mine\|all` | 列表（服务端按角色收口 scope） |
| POST | `/mcp/admin/approvals` | 提交申请 |
| GET | `/mcp/admin/approvals/{id}` | 详情（快照脱敏） |
| POST | `/mcp/admin/approvals/{id}/approve` | 通过并执行 |
| POST | `/mcp/admin/approvals/{id}/reject` | 驳回 |
| POST | `/mcp/admin/approvals/{id}/cancel` | 撤回 |
| GET | `/mcp/admin/approvals/{id}/secret` | 申请 `APP_CREATE` / `APP_RESET_SECRET` 通过后查看密钥（仅申请人/超管） |

## 7. 前端入口

- **审批中心** `/approvals`：待我审批 / 我发起的 / 全部；详情含快照 diff、审批意见、撤回、密钥查看。
- **应用与授权** `/permissions`：按角色显示“授权”或“申请授权”；应用凭证类操作提交 L3 审批。
- **MCP Server** `/servers`：创建/删除/连接配置变更按角色切换直写或申请。
- **用户管理** `/users`：管理员修改他人角色时提交 `USER_ROLE_UPDATE` 审批。
- 路由级角色门槛：直接输入 URL 也会被 `RequireLevel` 拦回概览页。

## 8. 数据库迁移

存量库执行 `docs/sql/migration.sql` 第 9 节：

1. `grant_request` 重命名为 `approval_request`（条件执行）；
2. 新增 `action` / `prompt_id` / `resource_id` / `user_id` / `payload` / 角色与意见字段；
3. 回填历史 `action` 与 `tenant_id`；
4. 补齐索引。

历史 `PENDING` 授权单沿用 `GRANT_SERVER` / `GRANT_TOOL`，迁移后仍可正常审批。
