# MCP 客户端兼容矩阵

> 目标：接入新客户端前先跑 `tools/mcp-client-probe.py`，把差异记录在这里，而不是靠猜。

## 1. 能力矩阵

| 客户端 | 传输 | 鉴权 | `nextCursor` 分页 | META 元工具 | 审批/确认 | 备注 |
|---|---|---|---|---|---|---|
| Codex CLI 0.163 | Streamable HTTP | Bearer（header 或 env var） | 待探针确认 | ✅ | `codex exec` 需 `--approve-for-me`；交互式手动允许 | CLI 默认不走系统代理；静态 token 会过期 |
| DSH Desktop | HTTP via `tools/dsh-mcp-sync.py` | Bearer | 待探针确认 | ✅ | 工具调用由宿主策略决定 | 工具名 `mcp__<serverKey>__<tool>` |
| Claude Desktop / Cursor | Streamable HTTP | Bearer | 客户端实现差异大 | ✅ | 首次调用可能弹确认 | 建议 Server 工具数 ≤ 50，或启用 META |
| Codex stdio bridge | stdio → HTTP | 脚本现签 JWT | 继承 supergateway | ✅ | 同 Codex | `tools/codex-pcb-bridge.sh` 自动续签 |

> “待探针确认”表示尚未用该客户端实测分页；在确认前，把 Server 的工具数控制在
> `MCP_TOOLS_PAGINATION_MIN_TOOLS`（默认 500）以内，避免客户端不翻页导致只看到第一页。

## 2. 探针用法

```bash
python3 tools/mcp-client-probe.py \
  --url http://127.0.0.1:8081/mcp/v1/pcb-server \
  --token-file ~/.codex/mcp-gateway.token
```

输出字段：

| 字段 | 含义 |
|---|---|
| `initialize` | 握手是否成功 |
| `toolsList` / `toolCount` | 首次 `tools/list` 是否成功、返回多少工具 |
| `nextCursor` | 是否返回分页游标 |
| `pagination` / `page2ToolCount` | 带 cursor 再请求是否成功 |
| `metaTools` / `searchTools` | 是否为 META 模式、`search_tools` 是否可用 |
| `meta` | `_meta` 中的预算、模式、token 估算 |

## 3. Codex 启动约定

推荐使用统一脚本：

```bash
# token 文件内容为一行 Bearer token
MCP_CODEX_TOKEN_FILE=~/.codex/mcp-gateway.token \
  tools/codex-run.sh "用 demo_pcb_server 的 add 计算 1+2"
```

脚本会：

- 自动设置 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`（默认 `http://127.0.0.1:7897`，可用 `MCP_CODEX_PROXY` 覆盖）；
- `NO_PROXY` 包含 `127.0.0.1,localhost`，避免 MCP 本地调用被代理；
- 使用 `codex exec --approve-for-me`，否则 MCP 工具调用会被默认 `never` 策略拒绝；
- 支持把 token 放在 `MCP_CODEX_TOKEN_FILE`，避免硬编码进 `config.toml`。

如果需要长期免维护，改用 stdio bridge：

```toml
[mcp_servers.demo_pcb_server]
command = "/bin/bash"
args = ["-lc", "/Users/lin/Downloads/MCP-Gateway/tools/codex-pcb-bridge.sh"]
```

## 4. 网关侧兼容策略

- 分页门槛默认 500：低于该值整包返回，避免不翻页客户端丢工具；
- 客户端白名单默认 `codex,claude,dsh,cursor,workbuddy`；
- 未识别客户端超过门槛时返回 `_meta.paginationRisk=true`，并记录分页埋点；
- 超过 500 个工具强烈建议启用 META，`tools/list` 只返回 3 个元工具，不依赖分页；
- `_meta.visibleTokens` / `returnedTokens` 分别表示“可见工具总成本”和“本次实际返回成本”。
