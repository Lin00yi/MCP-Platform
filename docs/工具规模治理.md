# 工具规模治理（分页 / META 元工具 / 预算 / Schema）

> 适用版本：2026-10-24 起
> 现行规则：**应用授权已移除**，不再有 WHITELIST/ALL 访问模式；Server 下全部启用工具对已认证用户可见。
> 规模治理只保留三层：**暴露模式（一次返回多少）**、**分页**、**预算告警**。
> 关联代码：`com.mcp.transfer.exposure.*`、`McpAggregateService`、`McpDiscoveryService`

---

## 1. 问题：工具定义会占满上下文

MCP 客户端在 `tools/list` 后把工具定义放进每一轮模型请求：

| 场景 | 约消耗 |
|---|---|
| 35 个工具 | 26K tokens |
| 58 个工具 | 55K tokens |
| 1,000 个工具 | 0.3M–0.7M tokens |
| 3,000 个工具 | 1M–2M tokens，直接超窗 |

工具越多，选错工具/传错参数的概率也越高。网关用「暴露模式 + 分页 + 预算」控制一次给模型多少，
而不是让客户端把全量拉下来。

---

## 2. 可见性（谁能看到）

- 应用授权、`app_tool_rel` / `app_prompt_rel` / `app_resource_rel` 已删除；
- Server 下**所有启用**的 Tool / Prompt / Resource 对已认证用户可见；
- `mcp_server.tool_access_mode` / `prompt_access_mode` / `resource_access_mode` 仅为存量库兼容保留，
  新数据固定写 `ALL`，控制台不再提供切换；
- 数据面 `tools/list` 与 `tools/call` 使用同一套规则：列表能看到，就能调用。

> 如果未来需要「按用户/角色收窄」，应新增明确的授权模型，而不是恢复旧的 app 白名单。

## 3. 两种暴露模式（一次返回多少）

`mcp_server.tool_exposure_mode`：

### 3.1 DIRECT（默认）

`tools/list` 返回全部可见工具，超过 `mcp.tools.page-size`（默认 200）时按 `mcp_tool.id` 游标分页：

```json
// 请求
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{"cursor":"djE6MjAw"}}
// 响应
{"result":{"tools":[...],"nextCursor":"djE6NDAw","_meta":{...}}}
```

- `mcp.tools.pagination-min-tools`（默认 500）：工具数低于该值时整包返回，不启用分页；
- `mcp.tools.pagination-clients`（默认 `codex,claude,dsh,cursor,workbuddy`）：已知支持分页的客户端；
- 未知客户端按 `pagination-unknown-policy`（默认 `PAGINATE`）处理，并在 `_meta.paginationRisk=true` 提示。

### 3.2 META（元工具 + 热工具）

`tools/list` 只返回：

- 端点级 4 个元工具：`search_tools` / `get_tool_schema` / `call_tool` / `read_result_chunk`；
- 该 Server 配置的热工具（`hot_tool_codes`，可按调用记录推荐）。

适合 Tool 数 > 100 或长尾明显的 Server。

```json
// 搜索
{"jsonrpc":"2.0","id":4,"method":"tools/call",
 "params":{"name":"search_tools","arguments":{"query":"订单 查询","top_k":10}}}

// 执行
{"jsonrpc":"2.0","id":5,"method":"tools/call",
 "params":{"name":"call_tool","arguments":{"name":"crm__order_query","arguments":{"orderNo":"A1"}}}}
```

- `search_tools` 只返回当前可见工具；
- `get_tool_schema` 支持 `compact` / `full` 双版本，并返回 token 估算；
- `call_tool.reason` 只用于审批/审计展示，不会传给目标工具；
- 超长结果触发分片时返回 `call_id`，用 `read_result_chunk` 继续读取。

## 4. 预算告警

管理台与 API 以 Server 为粒度统计：

- `totalTools` / `visibleTools` / `hotTools`；
- `estimatedTokens`（按 CJK 感知的近似 tokenizer）；
- `warnThreshold` / `maxThreshold`（默认 100 / 500，可按 Server 覆盖）；
- `overWarn` / `overMax` 标记，首页与 Server 列表会提示。

阈值只告警，不阻断；是否拆分 Server / 启用 META 由运营决定。

## 5. 管理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/mcp/admin/servers/budgets` | 全部 Server 预算快照 |
| `GET` | `/mcp/admin/servers/{id}/tool-budget` | 单 Server 预算 |
| `PUT` | `/mcp/admin/servers/{id}/tool-exposure` | 设置 `toolExposureMode` / 热工具 / 阈值 |
| `GET` | `/mcp/admin/servers/{id}/hot-tools/recommend?days=30&limit=20` | 按成功调用推荐热工具 |

请求示例：

```json
PUT /mcp/admin/servers/1/tool-exposure
{
  "toolExposureMode": "META",
  "hotToolCodes": ["order_query", "order_create"],
  "toolWarnThreshold": 50,
  "toolMaxThreshold": 200
}
```

应用授权相关字段（`toolAccessMode` / `promptAccessMode` / `resourceAccessMode` / `backfillExistingApps`）已删除，
传入会被忽略。

## 6. 配置项

> 日常只需要 `MCP_TOOLS_PROFILE=default|compact|large`；下表是单项覆盖变量（仍可用环境变量或
> `--mcp.tools.*` 启动参数设置），完整分层见 [配置说明](配置说明.md)。

| 覆盖变量 | 默认 | 说明 |
|---|---|---|
| `MCP_TOOLS_PAGE_SIZE` | 200 | `tools/list` 单页工具数 |
| `MCP_TOOLS_PAGINATION_MIN_TOOLS` | 500 | 低于该值不分页 |
| `MCP_TOOLS_PAGINATION_CLIENTS` | `codex,claude,dsh,cursor,workbuddy` | 支持分页的客户端子串 |
| `MCP_TOOLS_PAGINATION_UNKNOWN_POLICY` | `PAGINATE` | 未知客户端策略：`PAGINATE` / `ALL` |
| `MCP_TOOLS_META_ENABLED` | true | META 模式总开关 |
| `MCP_TOOLS_HOT_LIMIT` | 50 | 热工具上限 |
| `MCP_TOOLS_WARN_THRESHOLD` / `MCP_TOOLS_MAX_THRESHOLD` | 100 / 500 | 默认预算阈值 |
| `MCP_TOOLS_MAX_DESCRIPTION_LENGTH` | 1200 | 工具描述截断长度 |
| `MCP_TOOLS_CHUNK_STORE` | memory | 超长结果分片存储：`memory` / `redis` |
| `MCP_TOOL_RESULT_MAX_BYTES` | 1MB | 单次工具返回文本上限 |

## 7. Schema 瘦身

- `get_tool_schema` 默认 `compact`：只保留 name/description/必填参数，避免上下文占用；
- `detail_level=full` 返回完整 `inputSchema`；
- 支持 `tool_codes` 批量查询，一次拿多个工具的 schema；
- `_meta` 带 `visibleTokens` / `returnedTokens` / `tokenizer`，便于客户端判断是否需要分页或 META。

---

## 8. 存量迁移

- `tool_access_mode` / `prompt_access_mode` / `resource_access_mode` 保留列但固定 `ALL`；
- 旧 `app_*_rel` 表与审批动作已由 `docs/sql/20261021_drop_app_tables.sql` 清理；
- 新装环境直接用 `db/mysql/init.sql`，无需白名单相关脚本；
- 旧文档中的 `WHITELIST`、`exposure-impact`、`backfill` 接口均已删除，不再提供。
