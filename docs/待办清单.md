### P0 · 身份下传与上游鉴权（方案 A，骨架已实现，待接入用户服务/灰度）

| 项 | 内容 |
|---|---|
| **背景** | 下游 MCP Server 在内网且自研，需要把「应用 + 用户 + 客编」以可信方式传下去；当前上游无鉴权 |
| **方案** | 外部 `access-token` 验签 + `x-dsh-auth-token` 换用户信息 + 60s 内部 JWE/JWS 断言 + 下游验签 |
| **关键点** | ① appId 由客户端 `access-token` 提供，用户服务不返回 tenantIds；② 客编由用户信息服务根据 `x-dsh-auth-token` 返回**单个当前客编**（客户端不传）；③ 租户取当前调用的 MCP Server 的 `tenant_id`（应用为全局资源，不绑定租户）；④ 网关将会话绑定到该客编，后续不接受切换；⑤ 内部断言 `aud` 按下游限定、`jti` 防重放；⑥ 客编敏感，默认 JWE；⑦ 无 mTLS，需 HTTPS + 下游 IP 白名单 + 无日志 |
| **配套** | `mcp_app_owner`（应用归属）、`mcp_upstream`（下游 audience/公钥/静态凭证）、`UserInfoClient` 接口（未来网关并入用户服务时替换本地实现） |
| **详细方案** | 见《身份下传与上游鉴权改造方案.md》 |
| **验收** | 下游能验签并拿到 `app/user/tenant/customer`；多客编/切换/重放用例通过；客户端无法自报客编；token 与客编不落日志 |
| **当前状态** | 2026-10-21：用户 token 头统一为 `x-dsh-auth-token`，删除 `userId` 请求头兜底；Endpoint 入口也强制身份校验；本地 `.env` 已开启，生产仍由 `MCP_IDENTITY_ENABLED` 控制，待联调用户服务与下游公钥后灰度 |
| **涉及** | `McpAuthInterceptor`、`McpSessionCache`、`McpUpstreamClient`、`McpServiceImpl`、`McpAdminController`、新增 `UserInfoClient`/`InternalIdentityTokenService`/`McpIdentityContext` |

### P2 · 方案 C：OAuth2 Token Exchange（RFC 8693）

| 项 | 内容 |
|---|---|
| **触发条件** | 方案 A 落地后，下游 MCP Server 需要代表用户调用其他业务系统 |
| **目标** | 网关作为 STS：下游用内部断言换取「限定 audience + 限定 scope + 短期」的委托 token；或由网关统一代理下游出网 |
| **关键点** | ① 标准 `grant_type=urn:ietf:params:oauth:grant-type:token-exchange`；② `subject_token` 为内部断言，`audience` 为目标系统；③ 签发/兑换全链路审计；④ 令牌短 TTL、可撤销；⑤ 下游不得直接持有用户原始 token |
| **备注** | 本期不实施；先完成方案 A，避免同时改身份与委托两层 |

### P1 · stdio ↔ Streamable HTTP 桥（客户端兼容）

| 项 | 内容 |
|---|---|
| **背景** | WorkBuddy 等 MCP 客户端可能只支持 **stdio**（`command` / `args` / `env`），而网关只提供 **Streamable HTTP**，无法直连 |
| **触发条件** | 确认客户端配置里不支持 `url` / `headers`（WorkBuddy 官方文档只示范了 stdio 形式） |
| **目标** | 提供 `tools/mcp-stdio-bridge.js`（约 100 行 Node，无外部依赖），把 stdio 帧转成发往网关的 HTTP 请求 |
| **关键实现点** | ① 一行一个 JSON（不 pretty-print、不换行）<br>② `initialize` 响应头取 `Mcp-Session-Id`，后续 POST 与 SSE 都透传<br>③ env `MCP_TOKEN` → `Authorization: Bearer <jwt>`（网关已兼容）<br>④ 无 `id` 的通知（如 `notifications/initialized`）只 POST、不输出<br>⑤ 可选：开 GET SSE 中继服务端通知（`tools/list_changed`）<br>⑥ **日志只能写 stderr**（stdout 会污染协议）<br>⑦ 网络/5xx 转 JSON-RPC `-32603`，避免客户端 hang；401 明确提示 token 失效 |
| **验收标准** | ① 管道手工测试 `initialize` / `tools/list` / `tools/call` 通过；② MCP Inspector（stdio 模式）可列出工具并调通 `add(3,4)`；③ WorkBuddy 实连成功 |
| **可选增强** | 用 `app_secret` 在脚本内本地自签 JWT，免手工换 token（当前 JWT 1 小时过期） |
| **备选快验** | 先用 `npx -y supergateway --streamableHttp <网关URL> --header "Authorization: Bearer <jwt>"` 或 `uvx mcp-proxy` 验证链路，再决定是否自研 |
| **涉及文件** | 新增 `tools/mcp-stdio-bridge.js`；《MCP客户端接入指南.md》补充「stdio 桥接」章节 |
